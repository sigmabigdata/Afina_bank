Ключи шифрования

⬇ Скачать бэкап (ZIP)
⚠️ Критически важные файлы. Если потерять эти ключи — расшифровать данные невозможно ни через поддержку, ни через ФСБ, ни через космос.
Скачайте бэкап и сохраните его в менеджере паролей (1Password, KeePass) + на бумаге в сейфе. Три копии в трёх разных местах.

Что делать при передаче клиенту

Вариант 1: клиент генерирует сам (рекомендуется)

При первом развёртывании клиент выполняет на своём сервере: 

mkdir -p /opt/afina/secrets
openssl rand -base64 32 > /opt/afina/secrets/file.key
openssl rand -base64 32 > /opt/afina/secrets/pii.key
chown -R 999:999 /opt/afina/secrets
chmod 600 /opt/afina/secrets/*.key

Ключи никогда не покидают его сервер. Ты их не видишь. Клиент хранит их сам.

Вариант 2: ты генерируешь и передаёшь

Только через два разных защищённых канала:

  • Архив ключей — email / SFTP
  • Пароль от архива — SMS / голосом / другой мессенджер

Никогда в одном канале. Если канал перехватят — данные открыты.

Правила хранения

✅ МожноМенеджер паролей (1Password, KeePass) с мастер-паролем
✅ МожноБумага в сейфе (переписать base64 руками)
✅ МожноЗашифрованный архив на флешке в сейфе
✅ МожноS3 с шифрованием (если политика позволяет)
❌ НельзяВ git (даже в приватный репозиторий)
❌ НельзяВ .env файлы
❌ НельзяВ бэкап БД рядом с дампом
❌ НельзяВ открытых мессенджерах без E2E
❌ НельзяВ одном канале с зашифрованным архивом

Опасные действия

Перезапись ключей. Если файл ключа заменить новым — все данные, зашифрованные старым ключом, станут недоступны. Безвозвратно.
Никакой утилиты для ротации пока нет. Ключ = жизнь данных.
